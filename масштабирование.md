# Что нужно для масштабирования

Сейчас бот — один контейнер: SQLite рядом, long polling, напоминания шлёт
планировщик внутри процесса. Для школы и района этого хватает с запасом.
Если учеников станет заметно больше, менять пришлось бы вот что.

## База

SQLite — один файл, пишут в него по очереди. При росте нагрузки меняем на PostgreSQL:
в коде за это отвечают только две функции, `get_user` и `save_user`, схема из трёх
таблиц переносится как есть. Остальной код про базу ничего не знает.

## Кэш готовых тестов

По популярным темам («Дроби», «Смутное время», «Таблица Менделеева») ИИ каждый раз
генерирует почти одинаковые тесты. Можно кэшировать готовый quiz по теме и классу
и дёргать ИИ только если в кэше пусто — минус один запрос на кормёжку и ответ в разы быстрее.

## Webhook вместо long polling

Long polling держит постоянное соединение и ограничен примерно одним запросом в секунду.
У MAX есть `POST /subscriptions` (webhook на свой HTTPS-сервер, порт 443, секрет в
заголовке `X-Max-Bot-Api-Secret`) — тогда лимит уходит и один сервер обслуживает
заметно больше учеников. Дедупликация апдейтов у нас уже в БД, так что при переходе
на webhook ничего дважды не начислится.

## Планировщик напоминаний

Напоминания в 18:00 шлёт цикл внутри процесса бота. Он рассчитан на одну реплику:
если запустить два контейнера, напоминания уйдут дважды. Нужен внешний планировщик
(cron-задача или отдельный маленький сервис), который раз в день дёргает обход учеников.

## Стоимость ИИ

Один цикл кормёжки — это примерно 3 запроса: тест, объяснение, добивающие вопросы.
На дешёвой модели выходит порядка 1–2 копейки на цикл, то есть 1000 активных учеников
в день — примерно 10–20 рублей в день. Бесплатные тарифы OpenRouter тоже подходят,
но с очередями.

## Модерация

Ученик вводит произвольный текст, который уходит в ИИ. Перед отправкой стоит прогонять
его через список запрещённых слов и ограничивать частоту запросов на пользователя,
чтобы кто-нибудь не гонял бота ради прикола.

## Фото и файлы

Сейчас параграф принимается только текстом. Следующий шаг — фото страницы учебника
(нужно распознавание) и приём файлов. Для MAX это отдельный тип вложений, для нас — модуль OCR перед тем же самым промтом.
